# Phase 4: CI/CD Pipeline Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Three GitHub Actions workflows — unit tests on PR, E2E on push to main, and auto-deploy (Terraform + Azure SWA) on release with env routing by tag name.

**Architecture:** `pr.yml` runs Vitest. `push-main.yml` runs Playwright. `release.yml` detects env from tag (contains `rc` → nprod, else → prod), applies Terraform for that workspace, builds and deploys to Azure Static Web Apps.

**Tech Stack:** GitHub Actions, Vitest, Playwright, Terraform, Azure/static-web-apps-deploy@v1, hashicorp/setup-terraform@v3

```yaml
    branches: [main]
```

## Task 3: Push-Main Workflow — E2E Tests

**Files:**
- Create: `.github/workflows/push-main.yml`

> **Note:** The spec's `push-main.yml` definition omits env secrets. This workflow runs E2E tests against a live Next.js dev server, which requires Azure Tables and SMTP credentials (nprod values). These are set as repo-level secrets (not environment secrets) since `push-main.yml` doesn't target a GitHub Environment.

- [ ] **Step 1: Create .github/workflows/push-main.yml**

```yaml
# .github/workflows/push-main.yml
name: Push Main — E2E Tests

on:
  push:
    branches: [main]

jobs:
  e2e:
    name: E2E Tests (Playwright)
    runs-on: ubuntu-latest
    env:
      AZURE_TABLES_CONNECTION_STRING: ${{ secrets.AZURE_TABLES_CONNECTION_STRING_NPROD }}
      SMTP_HOST: ${{ secrets.SMTP_HOST }}
      SMTP_PORT: ${{ secrets.SMTP_PORT }}
      SMTP_USER: ${{ secrets.SMTP_USER }}
      SMTP_PASSWORD: ${{ secrets.SMTP_PASSWORD }}
      SMTP_FROM: ${{ secrets.SMTP_FROM }}
      AUTH_SECRET: ${{ secrets.AUTH_SECRET }}
      AZURE_KEYVAULT_URI: ${{ secrets.AZURE_KEYVAULT_URI_NPROD }}
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: lts/*
          cache: npm

      - name: Install dependencies
        run: npm ci

      - name: Install Playwright browsers
        run: npx playwright install --with-deps chromium

      - name: Run E2E tests
        run: npx playwright test

      - uses: actions/upload-artifact@v4
        if: always()
        with:
          name: playwright-report
          path: playwright-report/
          retention-days: 7
```

- [ ] **Step 2: Commit**

```bash
git add .github/workflows/push-main.yml
git commit -m "feat(ci): add push-main E2E workflow"
```

## Task 4: Release Workflow — Deploy

**Files:**
- Create: `.github/workflows/release.yml`

- [ ] **Step 1: Create .github/workflows/release.yml**

```yaml
# .github/workflows/release.yml
name: Release — Deploy

on:
  release:
    types: [published]

jobs:
  detect-env:
    name: Detect Target Environment
    runs-on: ubuntu-latest
    outputs:
      environment: ${{ steps.detect.outputs.env }}
    steps:
      - id: detect
        name: Resolve env from tag
        run: |
          if [[ "${{ github.ref_name }}" == *rc* ]]; then
            echo "env=nprod" >> $GITHUB_OUTPUT
          else
            echo "env=prod" >> $GITHUB_OUTPUT
          fi

  deploy:
    name: Deploy (${{ needs.detect-env.outputs.environment }})
    needs: detect-env
    runs-on: ubuntu-latest
    environment: ${{ needs.detect-env.outputs.environment }}
    env:
      ARM_CLIENT_ID: ${{ secrets.ARM_CLIENT_ID }}
      ARM_CLIENT_SECRET: ${{ secrets.ARM_CLIENT_SECRET }}
      ARM_TENANT_ID: ${{ secrets.ARM_TENANT_ID }}
      ARM_SUBSCRIPTION_ID: ${{ secrets.ARM_SUBSCRIPTION_ID }}
      DEPLOY_ENV: ${{ needs.detect-env.outputs.environment }}

    steps:
      - uses: actions/checkout@v4

      - name: Set up Terraform
        uses: hashicorp/setup-terraform@v3
        with:
          terraform_version: "~1.7"

      - name: Terraform init
        working-directory: terraform
        run: terraform init

      - name: Terraform workspace select
        working-directory: terraform
        run: |
          terraform workspace select "$DEPLOY_ENV" || terraform workspace new "$DEPLOY_ENV"

      - name: Terraform apply
        working-directory: terraform
        run: terraform apply -var-file="${DEPLOY_ENV}.tfvars" -auto-approve

      - uses: actions/setup-node@v4
        with:
          node-version: lts/*
          cache: npm

      - name: Install dependencies
        run: npm ci

      - name: Build
        run: npm run build
        env:
          AZURE_TABLES_CONNECTION_STRING: ${{ secrets.AZURE_TABLES_CONNECTION_STRING }}
          AUTH_SECRET: ${{ secrets.AUTH_SECRET }}
          AUTH_URL: ${{ secrets.AUTH_URL }}
          AZURE_KEYVAULT_URI: ${{ secrets.AZURE_KEYVAULT_URI }}

      - name: Deploy to Azure Static Web Apps
        uses: Azure/static-web-apps-deploy@v1
        with:
          azure_static_web_apps_api_token: ${{ secrets.AZURE_STATIC_WEB_APPS_API_TOKEN }}
          repo_token: ${{ secrets.GITHUB_TOKEN }}
          action: upload
          app_location: /
          output_location: ""
          # output_location is empty for Next.js SSR (SWA detects Next.js automatically)
```

- [ ] **Step 2: Commit**

```bash
git add .github/workflows/release.yml
git commit -m "feat(ci): add release deploy workflow with env detection"
```

## Task 5: Configure GitHub Repository

These steps are done in the GitHub repository settings UI (not code).

- [ ] **Step 1: Create GitHub Environments**

In repo → Settings → Environments → New environment:
1. Create `nprod` — no protection rules
2. Create `prod` — no protection rules

- [ ] **Step 2: Set environment secrets for `nprod`**

In Settings → Environments → nprod → Add secret:

| Secret | Value |
|---|---|
| `ARM_CLIENT_ID` | SP client ID from bootstrap `terraform output sp_client_id` |
| `ARM_CLIENT_SECRET` | SP client secret from bootstrap `terraform output -raw sp_client_secret` |
| `ARM_TENANT_ID` | Your Azure tenant ID |
| `ARM_SUBSCRIPTION_ID` | Your Azure subscription ID |
| `AZURE_STATIC_WEB_APPS_API_TOKEN` | `terraform output -raw swa_api_key` for nprod |
| `AZURE_TABLES_CONNECTION_STRING` | `terraform output -raw storage_connection_string` for nprod |
| `AZURE_KEYVAULT_URI` | `terraform output keyvault_uri` for nprod |
| `AUTH_SECRET` | Random 32-byte base64 string (`openssl rand -base64 32`) |
| `AUTH_URL` | Public URL of the nprod SWA (`https://<swa-hostname>`) |
| `SMTP_HOST` | SMTP server host |
| `SMTP_PORT` | SMTP server port |
| `SMTP_USER` | SMTP username |
| `SMTP_PASSWORD` | SMTP password |
| `SMTP_FROM` | From address for magic link emails |

- [ ] **Step 3: Set environment secrets for `prod`**

Repeat Step 2 for the `prod` environment, using prod Terraform outputs and prod SMTP credentials.

- [ ] **Step 4: Set repo-level secrets for E2E tests (push-main workflow)**

In Settings → Secrets and variables → Actions → New repository secret:

| Secret | Value |
|---|---|
| `AZURE_TABLES_CONNECTION_STRING_NPROD` | Same as nprod `AZURE_TABLES_CONNECTION_STRING` |
| `AZURE_KEYVAULT_URI_NPROD` | Same as nprod `AZURE_KEYVAULT_URI` |
| `AUTH_SECRET` | Same random secret |
| `SMTP_HOST` | SMTP host |
| `SMTP_PORT` | SMTP port |
| `SMTP_USER` | SMTP username |
| `SMTP_PASSWORD` | SMTP password |
| `SMTP_FROM` | From address |
